# Configuration Options

Every option Calendar Card Pro accepts, grouped by the part of the card it affects.

This page is the **index**: it tells you an option exists, what type it takes and what
it defaults to. The [feature pages](/features/core-settings) are where each option is
explained and demonstrated — where an option needs more than one line, this page links
to the page that owns it.

The font-size and icon-size rows below take a CSS value. A font size may be any CSS font size,
such as `14px`, `1.2em`, `120%` or `large`; an icon size, like `today_indicator_size`, is a
length such as `14px` or `1em`, never a percentage or a keyword. A size the card cannot read,
such as a negative one or a misspelled unit, falls back to the option's default.

::: tip Looking for a Starting Point?
[Usage](/guide/usage) has a complete first card, and each of the
[Example Stories](/reference/examples) is a whole card to copy and adapt. Snippets on this
site show only the options under discussion, so they are fragments rather than whole
cards.
:::

### Options With No Effect in Column View

`date_vertical_alignment` · `today_indicator_position` · `compact_events_to_show` ·
`compact_days_to_show` · `compact_events_complete_days` · `event_order` · `skip_first_events`

These describe a date cell, a compact budget or a list's order and continuation that the column
layout does not have. They
keep working in list view, including when a `view: column` card falls back to it on a
narrow dashboard. The editor hides their controls in the Columns editing workspace without
deleting stored values; see [Options for the Selected View](/features/editor#options-for-the-selected-view).

### Action Parameters

Each action option takes an object whose `action` key picks the behavior. In `tap_action` and
`hold_action`, every action but the card's own `expand`, `refresh`, `add-event`, `reset` and
`back` is run by Home Assistant; in `event_tap_action` and `event_hold_action`, every action but
`details`. The other keys are therefore Home Assistant's and depend on the action you chose:

`action` · `entity` · `navigation_path` · `navigation_replace` · `url_path` · `perform_action` · `data` · `target` · `confirmation`

The older `service` and `service_data` still work in place of `perform_action` and `data`.
`open_tab` is accepted for older configurations and does nothing: Home Assistant decides where a
`url` action opens its link.

`back` takes `navigation_path`, where it goes when no page of Home Assistant's is behind this
one; the card's other own actions, and `details`, take no further keys. `day_tap_action` takes
`action` alone: `add-event`, or `none`, its default. In `event_tap_action` and
`event_hold_action`, Home Assistant's keys take the event's fields in braces, such as `{title}`
or `{start}`; the title, location and description only in `data`, `service_data`, a
confirmation's `text`, or after the `?` or `#` of a URL or path.

| `refresh_interval`    | number  | `30`    | Minutes between refreshes where Home Assistant cannot push calendar changes: before 2026.5, or for a calendar failing to load, whose retries it also caps                      |
| `refresh_on_navigate` | boolean | `true`  | Load the events again in the background when the card appears, once the cached events it drew first are at least 5 seconds old. A failing calendar waits for its retry instead |
